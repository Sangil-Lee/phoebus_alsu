Git
===

Git 앱은 phoebus 안에서 로컬 Git 저장소를 다룹니다. 디스플레이(.bob), 설정 파일처럼
Git으로 관리하는 파일의 변경 확인, 커밋, 브랜치 작업, 원격 저장소와의 동기화를
phoebus를 벗어나지 않고 할 수 있습니다. 화면 구성은 Sourcetree와 비슷합니다.
Git 처리는 JGit으로 하므로 시스템에 ``git`` 명령이 없어도 됩니다.

메뉴 *Utility* → *Git* 또는 툴바의 Git 버튼으로 엽니다.
툴바의 *저장소* 칸에 경로를 입력하거나 *찾아보기...* 로 저장소 폴더를 고릅니다.
저장소 안의 하위 폴더를 골라도 상위의 ``.git`` 을 찾아 엽니다.

* *Clone...* : 원격 저장소 URL, 상위 폴더, 폴더 이름을 입력해 복제하고 엽니다.
  폴더 이름은 URL에서 자동으로 채워지며, 진행 상황은 툴바에 표시됩니다.
* *새 저장소...* : 입력하거나 고른 폴더에 빈 저장소를 만들고 엽니다.
* *최근* : 최근에 연 저장소 10개 중에서 다시 엽니다.
* *열린 파일* : phoebus 탭에 열려 있는 화면(.bob)과 파일 목록입니다. 고르면 그 파일의 이력/Blame 탭이 열립니다.
  지금 보고 있는 화면을 누가 언제 바꿨는지 바로 확인할 때 씁니다.

화면 구성
---------

툴바
    *Fetch*, *Pull*, *Push* (받을/보낼 커밋 수 표시), *Branch*, *Merge*, *Tag*, *Stash*, *Patch 적용...*, *Refresh*.
    작업이 진행 중이면 이름과 진행 표시가 나옵니다. 작업은 하나씩 차례로 실행됩니다.

자동 새로 고침
    작업 트리의 파일이나 저장소(커밋, 브랜치, stage 상태)가 바뀌면 잠시 뒤 자동으로 새로 고칩니다.
    다른 도구(명령행 git, 편집기)로 바꾼 내용도 반영됩니다. ``.gitignore`` 로 제외한 폴더는
    감시하지 않습니다. Git 탭을 선택하거나 그 창으로 돌아올 때도 새로 고칩니다.

사이드바
    * **작업 공간** : *파일 상태* 와 *이력* 화면 전환
    * **브랜치** : 로컬 브랜치. 현재 브랜치는 굵게, ↑ 보낼 커밋 수, ↓ 받을 커밋 수.
      더블클릭하면 checkout
    * **태그**, **원격** (원격 저장소별 브랜치, 마우스를 올리면 URL), **Stash**
    * **SUBMODULES** : submodule이 있을 때만 나옵니다. *초기화 안 됨*, *커밋 다름* (기록된 커밋과 다른 커밋이
      checkout됨)을 표시하고, 마우스를 올리면 URL과 기록된/실제 커밋을 보여 줍니다.

    각 항목의 우클릭 메뉴에서 checkout, 새 브랜치, 이름 변경, merge, rebase, 삭제,
    *현재 브랜치와 비교*, 태그 push/원격 태그 삭제, 원격 저장소 추가/URL 변경/*원격 저장소 설정...*/제거,
    stash 적용/꺼내기/삭제, submodule *초기화·업데이트*/*Git 탭에서 열기* 를 할 수 있습니다.

파일 상태
---------

* **Staged 파일** : 다음 커밋에 들어갈 변경 (HEAD 대비 index)
* **Unstaged 파일** : 아직 stage하지 않은 변경, 충돌, untracked 파일 (index 대비 작업 트리)

체크박스를 누르면 바로 stage 또는 unstage됩니다. *모두 Stage*, *모두 Unstage* 버튼과
우클릭 메뉴(여러 파일 선택 가능)도 있습니다. 우클릭의 *변경 버리기* 는 tracked 파일을
index 상태로 되돌리고 untracked 파일은 삭제합니다. 되돌릴 수 없으므로 확인 후 실행됩니다.

Untracked 파일의 우클릭 *무시하기...* 는 그 파일, 같은 확장자(``*.log``), 또는 그 폴더를
``.gitignore`` 에 추가합니다.

파일을 고르면 오른쪽에 diff가 나옵니다. *좌우 비교* 를 켜면 이전/이후를 나란히 보여 주고,
*공백 무시* 를 켜면 공백만 바뀐 줄을 숨깁니다.

Hunk 단위 작업
    diff의 각 변경 묶음(hunk, ``@@`` 줄) 앞에 버튼이 있습니다.
    Unstaged 파일은 *Hunk Stage* 와 *Hunk 버리기* (확인 후), Staged 파일은 *Hunk Unstage*.
    파일의 일부 변경만 커밋할 때 씁니다. 그 사이 파일이 바뀌어 hunk가 맞지 않으면
    적용하지 않고 새로 고침을 요청합니다. *공백 무시* 중에는 버튼이 나오지 않습니다.

줄 단위 작업
    diff에서 ``+``/``-`` 줄을 여러 개 고르고(Shift·Ctrl) 우클릭하면
    *선택한 줄 Stage*, *선택한 줄 버리기* (Unstaged), *선택한 줄 Unstage* (Staged)가 있습니다.
    고르지 않은 삭제 줄은 그대로 남고, 고르지 않은 추가 줄은 빠집니다.
    바뀐 덩어리의 일부만 고르면 고른 추가 줄이 고른 삭제 줄 자리에 들어가 줄 순서가 유지됩니다.

비교·되돌리기
    파일 우클릭 *비교* ▸ *HEAD* / *Index* / *브랜치·태그·커밋...* 은 작업 트리의 파일을 그 버전과 비교하는
    탭을 엽니다. *되돌리기* ▸ 같은 항목은 파일 내용을 그 버전으로 바꿉니다. 커밋 버전으로 되돌릴 때는
    *작업 트리만* 또는 *작업 트리와 index* 를 고르고, 그 버전에 없는 파일은 삭제됩니다.
    저장하지 않은 편집기가 그 파일을 열고 있으면 확인 창에 표시합니다.
    *Patch 만들기...* 는 고른 파일의 커밋하지 않은 변경(HEAD 대비)을 patch 파일로 저장합니다.

아래쪽에 커밋 메시지를 쓰고 *커밋* 을 누르면 staged 변경만 커밋됩니다.
*마지막 커밋 수정(amend)* 을 켜면 직전 커밋을 대신하며, 직전 메시지가 미리 채워집니다.
*커밋 후 바로 push* 를 켜면 커밋에 이어 현재 브랜치를 push합니다.

이력
----

모든 브랜치(또는 *모든 브랜치* 를 끄면 현재 브랜치)의 커밋을 그래프로 보여 줍니다.
브랜치는 초록, 원격 브랜치는 파랑, 태그는 노랑 라벨입니다.
기본으로 최근 100개 커밋을 읽고, *더 불러오기* 로 100개씩 더 읽습니다.
*검색* 칸에 글자를 넣고 Enter를 누르면 커밋 메시지, 작성자 이름/메일, 커밋 ID가 맞는 커밋을
전체 이력에서 찾습니다. 지우기(✕)로 전체 보기로 돌아옵니다.
커밋하지 않은 변경이 있으면 맨 위에 *커밋하지 않은 변경* 행이 나오고,
더블클릭하면 파일 상태 화면으로 갑니다.

커밋을 고르면 아래쪽 왼편에 그 커밋이 바꾼 파일 목록이 나옵니다.
맨 위 *모든 파일* 은 커밋 전체 diff를, 파일을 고르면 그 파일의 diff만 보여 줍니다.
이름이 바뀐 파일은 ``이전 경로 → 새 경로`` 로 표시됩니다.

커밋 우클릭 메뉴: 새 태그, 여기서 새 브랜치, cherry-pick, revert,
현재 브랜치를 여기로 reset (soft / mixed / hard), *여기서부터 interactive rebase...*,
*작업 트리와 비교*, *브랜치·태그·커밋과 비교...*, *Patch 만들기...*, 로그북 기록, 커밋 ID 복사.

커밋의 파일 목록에서 파일을 우클릭하면 *작업 트리와 비교*, *이 버전으로 되돌리기...*,
*이 버전 열기* 가 있습니다. *이 버전 열기* 는 그 커밋의 파일을 폴더째(연결 화면, 스크립트,
그림 등 상대 경로 참조가 그대로 동작하도록) 읽기 전용 임시 폴더에 꺼내 엽니다.
임시 폴더는 phoebus를 끝낼 때 지워집니다.

비교 탭
    두 버전(커밋, 브랜치, 태그, index, 작업 트리) 사이에 바뀐 파일 목록과 diff를 보여 줍니다.
    이름 변경도 찾으며(git과 같은 50% 기준), 작업 트리의 untracked 파일은 넣지 않습니다.
    *좌우 바꾸기* 로 방향을 바꾸고, 작업 트리를 비교할 때는 *새로 고침* 으로 다시 읽습니다.

화면 파일과의 연계
------------------

열기
    파일 상태 목록과 커밋의 파일 목록에서 파일을 더블클릭하면 기본 앱으로 엽니다
    (``.bob`` 은 Display Runtime). 우클릭의 *편집기로 열기* 는 화면 파일을 Display Editor로 엽니다.

File Browser
    File Browser에서 파일을 우클릭하면 *Git 파일 이력* 과 *Git에서 보기* 가 있습니다.
    파일이 속한 저장소를 자동으로 찾으며, 그 저장소의 Git 탭이 열려 있으면 그 탭을 씁니다.
    *Git에서 보기* 는 Git 탭을 열고, 바뀐 파일이면 파일 상태에서 그 파일을 선택합니다.

Git 작업 후 열린 화면
    pull, checkout, merge, reset, 변경 버리기 등 Git 작업이 열려 있는 파일을 바꾸면
    다시 불러올지 묻습니다. Display Runtime은 매크로를 유지한 채 다시 불러오고,
    Display Editor도 다시 불러옵니다. 저장하지 않은 수정이 있는 편집기는 다시 불러오지 않고
    경고만 합니다. 그 상태에서 저장하면 Git이 가져온 변경을 덮어쓰므로 주의하십시오.

위젯 단위 비교
    화면 파일(``.bob``, ``.bcf``)의 diff에서 *위젯 단위* 를 켜면 XML 대신 위젯별 변경을 보여 줍니다.

    * ``+ 추가: textupdate 'temp2'`` , ``- 삭제: label 'old'``
    * ``~ textupdate 'temp'   pv_name: SR:T1 → SR:T2``
    * 그룹·탭 안의 위젯은 ``(group 'g1')`` 처럼 위치를 함께 표시합니다.
    * 파일에 없는 속성은 *(기본값)* 입니다. 들여쓰기만 바뀌었으면 *위젯 변경 없음* 이 나옵니다.

    위젯은 부모, 종류, 이름으로 짝을 맞춥니다. 이름을 바꾸거나 다른 그룹으로 옮긴 위젯은
    삭제와 추가로 표시됩니다.
    위젯 줄을 더블클릭하면 그 화면을 Display Editor에서 열고(이미 열려 있으면 그 탭) 그 위젯을 선택합니다.

File Browser의 Git 상태 표시
    File Browser에서 Git 저장소 안의 파일 이름 앞에 상태를 표시합니다.

    * ``>`` 수정됨(주황), ``+`` 추가됨(초록), ``?`` untracked(회색), ``-`` 삭제됨, ``!`` 충돌(빨강, 굵게)
    * 바뀐 파일이 들어 있는 폴더는 ``>``, ``.gitignore`` 로 제외한 파일·폴더는 흐린 회색
    * 저장소 최상위 폴더 이름 뒤에 ``[브랜치 ↑보낼 ↓받을 *]`` (``*`` 는 커밋하지 않은 변경이 있음)

    저장소마다 상태를 백그라운드에서 읽고, 파일이나 저장소가 바뀌면 자동으로 갱신합니다.
    설정 ``file_browser_decorations=false`` 로 끌 수 있습니다.

Display Editor
    편집기에서 위젯(또는 빈 곳)을 우클릭하면 Git 메뉴가 있습니다.

    * *Git: HEAD 대비 바뀐 위젯 선택* : 저장하지 않은 수정까지 포함해 HEAD와 다른 위젯을 선택하고,
      추가·수정·삭제된 위젯 수를 알려 줍니다.
    * *Git: 위젯 이력* : 고른 위젯을 바꾼 커밋 목록(위젯 단위 blame)과 커밋별 속성 변경.
      저장하지 않은 수정은 맨 위 *커밋하지 않은 변경* 으로 나옵니다. 최근 200개 버전까지 봅니다.
    * *Git: 화면 이력* : 화면 파일의 파일 이력/Blame 탭
    * *Git: HEAD와 화면 비교* : 저장된 화면 파일을 HEAD와 비교하는 탭

커밋 전 검사
------------

*커밋* 을 누르면 stage한 파일을 먼저 검사합니다. 문제가 있으면 목록을 보여 주고,
*그래도 커밋* 또는 *취소* 를 고릅니다. 문제가 없으면 바로 커밋합니다.

화면 파일 (``.bob``, ``.bcf``)
    * **오류** : XML 형식이 잘못됨, Display Builder가 읽을 수 없음,
      참조하는 파일(연결 화면, embedded 화면, 그림, 스크립트, ``.plt`` 등)이 없음
    * **경고** : 참조하는 파일이 있지만 이번 커밋에 들어가지 않음(untracked 또는 stage 안 됨),
      알 수 없는 위젯 종류, 저장소 밖 참조 파일이 없음, PV 이름이 규칙과 다름(``pv_name_pattern`` 설정 시)

    매크로(``$(...)``)가 들어간 경로, URL, 내장 스크립트, ``loc://`` · ``sim://`` PV는 검사하지 않습니다.

파이썬 스크립트 (``.py``)
    Display Runtime과 같은 Jython(파이썬 2.7) 기준으로 문법을 검사합니다(경고).

설정 ``check_before_commit=false`` 로 끌 수 있습니다.

로그북 기록 (Olog)
------------------

push가 성공하면 *push한 커밋을 로그북에 기록할까요?* 를 묻습니다. 기록을 고르면 Olog 작성 창이
다음 내용으로 미리 채워져 열립니다. 내용을 확인·수정한 뒤 Olog 사용자로 제출합니다.

* 제목 : ``Git: 저장소 짧은ID 메시지`` (커밋이 여럿이면 ``Git: 저장소 브랜치 커밋 N개``)
* 본문 : 저장소, push 대상(원격 URL), 브랜치, 커밋별 메시지·작성자·날짜,
  바뀐 화면의 위젯 변경 요약, 그 밖에 바뀐 파일
* 첨부 : 커밋 전체 diff (``.diff``)
* 로그북·태그·Level : 설정 ``logbooks``, ``log_tags``, ``log_level`` (비우면 로그북 앱 기본값)

이력의 커밋 우클릭 *로그북에 기록...* 으로 특정 커밋을 기록할 수도 있습니다.
push 후 묻지 않게 하려면 ``logbook_after_push=false`` 로 설정합니다.

파일 이력과 Blame
-----------------

파일 상태 목록이나 커밋의 파일 목록에서 파일을 우클릭하고 *파일 이력* 을 고르면
그 파일만의 탭이 열립니다.

* **이력** : 그 파일을 바꾼 커밋과, 각 커밋에서의 그 파일 diff.
  이름이 바뀐 파일은 바뀌기 전 이력까지 따라가며, 당시 경로가 다르면 *경로* 칸에 표시됩니다.
* **Blame** : 줄마다 마지막으로 바꾼 커밋, 작성자, 날짜.
  같은 커밋에서 온 줄은 같은 배경으로 묶이고, 커밋하지 않은 줄은 노란 배경에 *(커밋 안 됨)* 으로 표시됩니다.
  줄을 더블클릭하면 이력에서 그 커밋을 보여 줍니다.

Pull과 Push
-----------

*Pull* 은 현재 브랜치의 upstream에서 받아 옵니다. *merge 대신 로컬 커밋을 rebase* 를 고르면
아직 push하지 않은 로컬 커밋을 받아 온 커밋 위로 옮겨 이력을 한 줄로 유지합니다.

*Push* 창에서 원격 저장소와 브랜치를 고릅니다.

* upstream이 없는 새 브랜치는 같은 이름으로 push되고, 그 브랜치가 upstream으로 설정됩니다.
* *모든 태그 push* 는 태그도 함께 보냅니다.
* *강제 push (with lease)* 는 이미 push한 커밋을 amend 또는 rebase한 뒤에 씁니다.
  원격 브랜치가 마지막 fetch 이후 그대로일 때만 덮어쓰므로, 그 사이 다른 사람이 push한
  커밋을 지우지 않습니다(``git push --force-with-lease`` 와 같음).

Merge, Rebase와 충돌
--------------------

*Merge* 는 고른 브랜치를 현재 브랜치로 합칩니다. 충돌이 나면 파일 상태 화면으로 바뀌고
충돌 파일이 *Conflict* 로 표시되며, merge 메시지가 미리 채워집니다.

충돌 파일은 병합 도구로 해결하거나, 작업 트리에서 직접 고친 뒤 stage하거나, 우클릭으로 한쪽을 고릅니다.

* *병합 도구...* (충돌 파일 더블클릭) : 아래 참고
* *내 것으로 해결 (ours)* : 현재 브랜치의 내용
* *상대 것으로 해결 (theirs)* : 합치는 브랜치의 내용

병합 도구
    위에 *내 것*, *Base (공통 조상)*, *상대 것*, 아래에 *결과* 가 나옵니다. 충돌 부분은 빨강,
    해결한 부분은 고른 쪽 색으로 표시됩니다. 충돌마다 *내 것*, *상대 것*, *둘 다 (내 것 먼저)*,
    *둘 다 (상대 것 먼저)* 를 고르거나 *직접 편집...* (결과 줄 더블클릭)으로 고칩니다.
    고르면 다음 미해결 충돌로 넘어갑니다. *저장하고 해결로 표시* 는 결과를 저장하고 stage합니다.
    미해결 충돌이 남아 있으면 충돌 표시(``<<<<<<<``)와 함께 저장만 할지 묻습니다.
    줄바꿈(CRLF)과 끝 줄바꿈 유무는 원래 파일대로 유지합니다.
    한쪽에서 삭제한 파일과 바이너리 파일은 *내 것/상대 것으로 해결* 을 쓰라고 안내합니다.

화면 파일의 위젯 단위 병합
    ``.bob``, ``.bcf`` 충돌은 병합 도구에 *위젯 단위* 탭이 먼저 나옵니다(*텍스트 줄 단위* 탭도 있음).
    위젯과 속성마다 3-way로 판단해, 한쪽만 바꾼 속성과 한쪽에서만 추가·삭제한 위젯은 자동으로 반영하고
    (*충돌 없이 상대 것에서 가져온 변경* 목록), 양쪽이 다르게 바꾼 속성과 한쪽은 삭제·다른 쪽은 수정한 위젯만
    *충돌* 표에 나옵니다. 충돌마다 *선택* 칸에서 내 것/상대 것을 고르거나 *모두 내 것*, *모두 상대 것* 을 누릅니다.
    결과는 내 것 파일을 기준으로 바뀐 부분만 고쳐 서식과 위젯 순서를 유지하며, 저장 전에 Display Builder로
    읽히는지 확인합니다. 줄 단위로는 충돌하는 위젯 순서 변경·들여쓰기 차이도 위젯 단위로는 충돌하지 않습니다.
    탭 위젯의 탭 구성처럼 위젯을 담은 속성이 양쪽에서 바뀌면 위젯 단위 탭 없이 텍스트 병합만 나옵니다.

그 다음 커밋하거나, *Merge 중단* 으로 취소합니다.
cherry-pick, revert에서 난 충돌도 같은 방식으로 처리합니다.

브랜치 우클릭의 *현재 브랜치를 여기로 rebase...* 는 현재 브랜치의 커밋을 그 브랜치 위로 옮깁니다.
충돌이 나면 커밋 버튼 대신 *Rebase 계속*, *이 커밋 건너뛰기*, *Rebase 중단* 이 나옵니다.
충돌을 해결해 stage한 뒤 *Rebase 계속* 을 누르면 다음 커밋으로 넘어갑니다.
Rebase 중에는 git의 정의대로 *ours* 가 옮겨 가는 대상 브랜치, *theirs* 가 옮기는 커밋입니다.

Interactive rebase
    이력에서 커밋을 우클릭해 *여기서부터 interactive rebase...* 를 고르면, 그 다음 커밋부터
    현재 브랜치 끝까지를 오래된 순서로 보여 줍니다. 커밋마다 동작을 고르고 *위로*/*아래로* 로 순서를 바꿉니다.

    * ``pick`` 그대로, ``reword`` 메시지 수정, ``edit`` 멈춰서 amend,
      ``squash`` 앞 커밋과 합치고 메시지 편집, ``fixup`` 앞 커밋과 합치고 앞 메시지 유지, ``drop`` 제거
    * 이미 push한 커밋(*Push됨* 표시)이 있으면 경고합니다. 다시 쓰면 강제 push가 필요합니다.
    * reword와 squash는 진행 중에 메시지 편집 창이 뜹니다.
    * ``edit`` 에서 멈추면 파일을 고쳐 stage하고 *마지막 커밋 수정(amend)* 으로 커밋한 뒤 *Rebase 계속* 을 누릅니다.
    * 충돌은 일반 rebase와 같이 처리합니다. merge 커밋이 들어 있으면 시작하지 않습니다.

Patch
    이력의 커밋 우클릭 *Patch 만들기...* 는 그 커밋을 ``git format-patch`` 형식으로 저장합니다
    (``git am`` 으로 적용 가능, 작성자·메시지 유지). 툴바의 *Patch 적용...* 은 patch 파일(unified diff 또는
    format-patch)을 골라 바뀔 파일을 보여 준 뒤 작업 트리에 적용합니다. 맞지 않으면 적용하지 않고 오류를 보여 줍니다.

원격 저장소 인증
----------------

HTTPS
    사용자 이름과 비밀번호(또는 액세스 토큰)를 묻습니다.
    *보안 저장소에 저장* 을 고르면 호스트별로 phoebus 보안 저장소에 저장되고,
    인증에 실패하면 다시 묻습니다.

SSH
    ``ssh_directory`` (기본 ``~/.ssh``)의 기본 키와 ``config`` 를 사용합니다.
    키 passphrase와 처음 접속하는 서버의 호스트 키 확인은 대화상자로 묻습니다.
    ssh-agent는 지원하지 않습니다.

원격 저장소 설정
    사이드바 원격 저장소 우클릭 *원격 저장소 설정...* 에서 fetch URL, push URL(비우면 fetch URL),
    fetch/push refspec(한 줄에 하나), *Fetch할 때 원격에서 지워진 브랜치 정리 (prune)*,
    태그 가져오기(가져온 커밋의 태그 / 모든 태그 / 안 가져옴)를 바꿉니다. ``.git/config`` 에 저장됩니다.
    prune 설정이 없는 저장소는 이전처럼 fetch할 때 정리합니다.

Submodule
    *Clone...* 의 *submodule 포함* 을 켜면 submodule까지 받습니다. 사이드바 SUBMODULES의
    *초기화·업데이트* 는 submodule을 받아 기록된 커밋을 checkout합니다(``git submodule update --init``).
    submodule에서 다른 커밋을 checkout하면 파일 상태에 바뀐 것으로 나오며, stage·커밋하면 기록된 커밋이 바뀝니다.

설정
----

``git_preferences.properties`` 의 항목을 phoebus 설정 파일에서
``org.phoebus.applications.git/항목=값`` 으로 바꿀 수 있습니다.

.. code-block:: properties

    # 시작할 때 열 저장소. 비우면 선택하지 않은 상태로 시작
    org.phoebus.applications.git/default_repository=

    # 이력에서 한 번에 읽는 커밋 수
    org.phoebus.applications.git/log_count=100

    # SSH 키, known_hosts, config 가 있는 폴더
    org.phoebus.applications.git/ssh_directory=$(user.home)/.ssh

    # 사용할 SSH 개인키. 비우면 ssh_directory의 기본 키 사용
    org.phoebus.applications.git/ssh_private_key=

    # fetch/pull/push 타임아웃(초)
    org.phoebus.applications.git/remote_timeout=30

    # 파일/저장소가 바뀌거나 탭·창으로 돌아올 때 자동 새로 고침
    org.phoebus.applications.git/auto_refresh=true

    # 커밋 전 검사
    org.phoebus.applications.git/check_before_commit=true

    # PV 이름 규칙(정규식). 비우면 검사하지 않음. 예: [A-Z0-9]+(:[A-Za-z0-9_]+)+
    org.phoebus.applications.git/pv_name_pattern=

    # push 후 로그북 기록을 제안
    org.phoebus.applications.git/logbook_after_push=true

    # 로그북 기록에 쓸 로그북과 태그 (쉼표로 구분, 비우면 기본값)
    org.phoebus.applications.git/logbooks=
    org.phoebus.applications.git/log_tags=

    # 로그북 기록의 Level (예: Info). 비우면 로그북 앱 기본값
    org.phoebus.applications.git/log_level=

    # File Browser에 Git 상태 표시
    org.phoebus.applications.git/file_browser_decorations=true

화면 문구는 JVM 언어 설정을 따릅니다. 한국어 환경에서는 한국어로 나오며,
영어로 보려면 ``-Duser.language=en`` 으로 실행합니다.

제한 사항
---------

* ssh-agent와 GPG 서명 커밋은 지원하지 않습니다(JGit 확장 모듈과 BouncyCastle·JNA 의존성 추가가 필요).
* Windows에서는 검증하지 않았습니다.
* 위젯 단위 병합과 위젯 이력은 위젯 이름으로 짝을 맞추므로, 이름을 바꾼 위젯은 삭제·추가로 다룹니다.
  위젯 단위 병합은 상대 쪽의 위젯 순서 변경을 반영하지 않습니다(내 것 순서 유지).
* *되돌리기* 와 *이 버전 열기* 는 저장소의 내용을 그대로 쓰므로 ``core.autocrlf`` 같은 줄바꿈 변환은 하지 않습니다.
* 자동 새로 고침은 작업 트리 폴더를 최대 5000개까지 감시합니다. 더 큰 저장소나
  파일 변경 알림이 없는 파일 시스템(일부 네트워크 드라이브)에서는 탭·창 전환 시 새로 고침과
  *새로 고침* 버튼을 쓰십시오.
* *Merge 중단* 과 hard reset은 커밋하지 않은 변경을 모두 버립니다.
* 태그 push와 원격 태그 삭제는 ``origin`` (없으면 첫 번째 원격 저장소)을 대상으로 합니다.
